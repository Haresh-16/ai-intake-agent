# Streamlit Defendant Intake UI

## Overview
Web interface for defendants/prospective clients to interact with the AI Intake System. This is a compliance-first, user-friendly interface that guides prospects through an 8-stage intake conversation.

## Features
- **Guided Intake Conversation**: AI-powered chat interface with stage-based progress tracking
- **Compliance-First Design**: Prominent disclaimers, no legal advice, human review reminders
- **Auto-Finalization**: Automatically generates intake summary when conversation completes
- **PII Protection**: All sensitive data is redacted by the backend before storage
- **Mobile-Responsive**: Works on desktop, tablet, and mobile devices

## Architecture
This is a **separate Streamlit application** that communicates with the FastAPI backend via HTTP. It runs on a different port (8501) and makes REST API calls to the backend (port 8000).

## Prerequisites
- Python 3.11+
- Running FastAPI backend (see main README.md)
- Dependencies installed from `requirements-streamlit.txt`

## Installation

1. **Install dependencies**:
   ```bash
   pip install -r requirements-streamlit.txt
   ```

2. **Configure backend URL** (optional):
   Create a `.env.streamlit` file:
   ```env
   STREAMLIT_BACKEND_URL=http://localhost:8000
   STREAMLIT_APP_TITLE=Legal Intake Assistant
   STREAMLIT_SHOW_STAGE_PROGRESS=true
   STREAMLIT_AUTO_FINALIZE_ON_WRAP=true
   ```

## Running the Application

### Option 1: Direct Streamlit command
```bash
streamlit run streamlit_app/main.py
```

### Option 2: Convenience launcher
```bash
python run_streamlit.py
```

The app will open automatically in your browser at: `http://localhost:8501`

## Usage Flow

1. **Prospect Form**: User provides contact information and consents to AI intake
2. **Chat Conversation**: 8-stage guided conversation with AI assistant
   - Stage 1: Initial Greeting
   - Stage 2: Consent Collection
   - Stage 3: Fact Gathering
   - Stage 4: Information Review
   - Stage 5: Follow-up Questions
   - Stage 6: Evidence Collection
   - Stage 7: Comprehensive Review
   - Stage 8: Defendant Information
   - Stage 9: Final Review
3. **Auto-Finalization**: System generates intake summary (when stage 9 is reached)
4. **Summary View**: User sees summary and next steps
5. **New Intake**: User can start a fresh conversation

## Compliance Features

This UI enforces strict compliance boundaries per the project requirements:

1. **Non-Dismissible Compliance Banner**: Always visible at the top of every page
   - "This is an AI intake assistant, NOT a lawyer"
   - "This chat does NOT provide legal advice"
   - "This chat does NOT create an attorney-client relationship"

2. **Consent Checkpoint**: Required checkbox before starting conversation
   - User must explicitly acknowledge AI assistant nature

3. **No Legal Advice Language**:
   - Agent messages labeled "Assistant" (never "Lawyer")
   - Robot emoji (🤖) avatar
   - Neutral recommendation language

4. **Human Review Reminders**: Throughout the conversation
   - "All information will be reviewed by a human attorney"
   - "This summary was generated by an AI assistant"

5. **PII Redaction**: Handled automatically by backend
   - SSN, account numbers, DOB are redacted before storage
   - UI displays only sanitized content

## Troubleshooting

### "Unable to connect to server"
- Verify FastAPI backend is running on port 8000
- Check `STREAMLIT_BACKEND_URL` configuration in `.env.streamlit` or `config.py`
- Ensure no firewall blocking localhost connections

### Page refresh loses conversation
- This is **expected behavior** (current session only)
- Streamlit session state is in-memory and lost on page refresh
- User should start a new intake after refresh
- Future enhancement: Add conversation_id to URL query params for recovery

### Slow responses
- Check backend LLM configuration (stub mode vs. real provider)
- Increase timeout in `api_client.py` if needed (default: 30 seconds)
- Verify backend database is accessible

### Stage progress not updating
- Check that backend is returning `current_stage` in API responses
- Verify stage names match between frontend and backend
- Check console for JavaScript errors

## API Integration

### Endpoints Used

1. **POST /api/intake/messages**
   - Creates new conversation or adds to existing
   - Returns: conversation_id, sanitized_content, suggested_next_prompt, current_stage

2. **POST /api/intake/conversations/{id}/finalize**
   - Auto-called when current_stage == "wrap"
   - Returns: Complete intake summary JSON

3. **GET /api/intake/conversations/{id}**
   - Optional: For error recovery (not currently used)

### Error Handling

The UI handles various error scenarios:
- **Network/Connection Errors**: User-friendly message with retry suggestion
- **Timeout Errors**: Clear timeout message
- **Backend Validation Errors (400)**: Invalid input message
- **Backend Server Errors (500)**: Server error message
- **Conversation Not Found (404)**: Reset to new intake

## Security Considerations

- **No Local Storage**: All data in session state (in-memory only)
- **Backend PII Redaction**: Sensitive data masked before persistence
- **Session-Only Data**: Clears on browser close
- **CSRF Protection**: Enabled in Streamlit config
- **No Authentication**: Current scope is unauthenticated intake (add auth for production)
